## Proposed architecture and budgets (not canon, not measured)
- Keep one authoritative fictional clock and event-driven scheduler. Do not simulate every millisecond; never advance time while reading, app is backgrounded or phone is idle. Technical continuation preserves same admitted action, real work budget and exact committed effects; no fake completion, dropped facts, duplicate RNG or altered difficulty. Wall-clock is profiling/technical yield only. 12 reviewed NPCs first, 128 living cap / 32 regional generation budget provisional. Nearby and distant detail may differ but actual causal effects, important history and private knowledge persist. Never kill/delete NPCs to fit RAM.
- Use incremental indexed reads/writes and bounded actor-specific decision context instead of full archive replay every choice. Preserve immutable history, provenance and all three rewind slots. SQLite atomic current-head publication with authoritative CAS and epoch fencing; full historical rewind/external judgement still D7. No second authoritative cache or shadow ledger, no arbitrary memory truncation. Store immutable versioned catalog separately, fetch acquired/known techniques on demand, no eager per-actor copies of all 10,000 definitions; 10,000 placeholder rows are NOT 10,000 real abilities. Keep private IDs/records out of actor-visible views.
- Native text scrolling: virtualized paragraph history, stable keys, append only committed scoped receipts, lazy older pages. Native frame responsiveness target 60Hz baseline (16.67ms frame interval), not mandatory 120Hz; short cooperative JS slices proposed <=8ms where practical, no arbitrary split of atomic domain boundaries. Benchmark release build, not debugger/dev mode. Use async native DB APIs with reviewed serialized transaction semantics, never allow unrelated async writes inside open transaction. No network/cloud inference required for core loop.
- Initial acceptance targets for A54 6GB: warm common Continue p95 <=250ms to first safe visible result, p99 <=1000ms for bounded ordinary local actions (long simulated horizons may show pending, never fictitious result); input response p95 <=100ms; scrolling >=55fps median on 60Hz baseline, p95 frame <=33.4ms; startup to usable current-head <=3s warm / <=5s cold. Proposed total app PSS <=256MiB steady / <=400MiB peak in normal scenario, no unbounded growth, measure 30-minute repeated workload and distinguish retained archive storage from resident heap. Idle while reading: no fictional advancement and no periodic simulation loop; report actual CPU/battery/thermal behavior. All targets provisional, revise using device data rather than remove core requirements. No claim of achieved device performance.
- Run matrix: 2-actor M1-A engineering fixture then 12 validated NPCs then 128 synthetic stress actors, with 10k indexed placeholder definitions for capacity only; separate real ability validation. Record cold/warm start, 100 ordinary actions with input/commit/render timing, 30-minute varied travel/work/rest/choice, scroll long history, repeat technical retry, normal close/reopen, ordinary background/resume, low-space synthetic DB failure, three-slot actual restore when implemented, stale epoch, privacy checks, deterministic desktop/mobile fixture parity. Measure p50/p95/p99/max, counts, PSS/RSS/heap, DB/WAL size, frame timings, errors, temperature and battery delta under recorded conditions. Android lifecycle recovery never substitutes for authorized rewind. No automated force-stop, uninstall, real save alteration or paid build. Owner-only force-stop tests separate. Device evidence required before any release claim.
